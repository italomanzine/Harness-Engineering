Spec como contrato

TDD + BDD + SDD

TDD

Test Driven Development

Escreva o teste antes da implementação — spec no nível unitário.

test('soma', () => {
  expect(soma(2,3)).toBe(5);
});

BDD

Behavior Driven Development

Descreva o comportamento em linguagem de negócio antes de implementar.

O que é Harness Engineering

É a disciplina de engenharia de software responsável por construir e manter os arreios do desenvolvimento.

O problema

Agentes que não são confiáveis

One Shot Hero

Tenta fazer tudo de uma vez e perde o contexto.

Vitória Prematura

Declara a tarefa pronta, mesmo incompleta.

Amnésia entre Sessões

Perda de contexto e memória entre execuções.

Falta de Validação Real

Marca features prontas sem testes ou lint executados por sensores externos.

Slope Acumulado

Degradação gradual: mesmo compilando, acumula dívida técnica e viola a arquitetura.

Harness Engineering: rédeas no agente

Feed Forward — specs, guias e convenções (preventivo) Feedback — sensores corrigem o modelo em loop
Fonte: Spec Driven chegou no limite — Harness Engineering é o próximo passo (YouTube)

Prática

Como trabalhar com Harness

01

Orquestração de Agentes

Separe responsabilidades: um agente implementa, outro valida/testa. Nunca um só para tudo.

02

Contratos

O agente define uma lista de tarefas (o contrato) validada antes da execução. Evita loops infinitos.

03

Sensores Externos

Qualidade julgada por ferramentas determinísticas (testes, lint), não pela LLM. Resultado binário 0/1.

04

Progresso e Contexto

Arquivos de progress e scripts de bootstrap mantêm o estado e evitam amnésia entre sessões.
